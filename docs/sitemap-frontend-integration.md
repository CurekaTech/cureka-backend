# Sitemap — frontend integration

This is the contract for the Next.js / CDN layer. The backend already generated the XML. **Do not query product, category, or CMS APIs to build a sitemap.**

## Frontend work (brief)

1. **Rewrite** storefront `/sitemap.xml` and `/sitemaps/*` to the backend public endpoints.
2. **Read the API base URL from env** (never hardcode host). Same rewrite works on local, staging, and production.
3. **Do not generate** sitemap XML in Next.js (`app/sitemap.ts`, catalog API calls, etc.).
4. In Google Search Console, submit **only** `{STOREFRONT}/sitemap.xml`.

## Env — API base URL

The rewrite destination **must** come from an environment variable so each server can point at its own API:

| Env (frontend) | Example |
|---|---|
| Local | `http://localhost:3000` |
| Staging | `https://api-staging.cureka.com` |
| Production | `https://api.cureka.com` |

Suggested names (use whichever already exists in the storefront): `NEXT_PUBLIC_API_ORIGIN`, `API_BASE_URL`, or `BACKEND_URL`. Strip a trailing slash. Do not bake `https://api.cureka.com` into `next.config.js`.

```env
# .env.local / .env.staging / .env.production
NEXT_PUBLIC_API_ORIGIN=http://localhost:3000
```

`<loc>` values inside the XML are **not** the frontend’s job. Those use the backend `SITEMAP_BASE_URL` / `STOREFRONT_URL` (the public storefront origin, e.g. `https://www.cureka.com` or `http://localhost:3001`).

## What the backend provides

Pre-generated XML, stored in GCS (production) or local `uploads/sitemaps/` (dev). Served as raw XML:

| Storefront URL | Backend stream |
|---|---|
| `{STOREFRONT}/sitemap.xml` | `GET {API}/api/v1/public/sitemap.xml` |
| `{STOREFRONT}/sitemaps/static.xml` | `GET {API}/api/v1/public/sitemaps/static.xml` |
| `{STOREFRONT}/sitemaps/products/products-1.xml` | `GET {API}/api/v1/public/sitemaps/products/products-1.xml` |
| `{STOREFRONT}/sitemaps/brands.xml` | `GET {API}/api/v1/public/sitemaps/brands.xml` |
| … same pattern for categories, health-concerns, wellness-goals, collections, blogs, support, cms | |

`{API}` = frontend env (API origin). `{STOREFRONT}` = public site origin.

The index file **only** lists child sitemap URLs on the storefront origin. Child files contain `<url><loc>` + `<lastmod>`.

Physical objects live under the existing Cureka GCS bucket (`sitemaps/...`). The bucket is private. The frontend must **not** link Google at signed GCS URLs.

## How Next.js should expose the sitemap

Add rewrites so crawlers see the storefront domain. Example `next.config.js`:

```js
const API = (process.env.NEXT_PUBLIC_API_ORIGIN || process.env.API_BASE_URL || '').replace(
  /\/+$/,
  '',
);

if (!API) {
  throw new Error('NEXT_PUBLIC_API_ORIGIN or API_BASE_URL must be set for sitemap rewrites');
}

module.exports = {
  async rewrites() {
    return [
      {
        source: '/sitemap.xml',
        destination: `${API}/api/v1/public/sitemap.xml`,
      },
      {
        source: '/sitemaps/:path*',
        destination: `${API}/api/v1/public/sitemaps/:path*`,
      },
    ];
  },
};
```

That covers nested paths such as `/sitemaps/products/products-1.xml`.

Do **not** implement `app/sitemap.ts` / `getServerSideProps` that loads catalog data.

If the storefront already has a CDN/proxy in front of Next.js, keep it. Honor the backend `Cache-Control`:

```http
Content-Type: application/xml; charset=utf-8
Cache-Control: public, max-age=300, s-maxage=300, stale-while-revalidate=3600
```

Do **not** add a new sitemap CDN or cache product. A 5-minute edge TTL is enough for Google to pick up replacements without extra invalidation APIs.

## No database calls

Frontend must NOT query backend product/category APIs to generate the sitemap.

The XML is already generated by the backend worker.

## Static + dynamic URLs

The sitemap includes both:

- **Static hub pages** (`/`, `/product-brands`, `/blog`, `/support`, …)
- **Database-driven pages** (products, categories, brands, health concerns, wellness goals, collections, blogs, support articles, CMS/policy pages)

Product URLs come from **`products.slug` and, when set, variant `product_page_url`**. Most products have no `product_page_url`; those use `/shop/{category-path}/{slug}` only. Never per SKU. Facet/sort/`?page=` variants are not included.

## Google Search Console

Submit **only** the storefront index (production origin), not every child file:

```text
https://www.cureka.com/sitemap.xml
```

Google discovers children from the index.

## Verification checklist

- `/sitemap.xml` returns XML (`Content-Type` contains `xml`)
- sitemap index contains child sitemap URLs on the **storefront** origin (from backend `SITEMAP_BASE_URL`), not the API host
- child sitemap URLs are accessible (HTTP 200)
- rewrite destination uses env API base URL (works on local / staging / prod)
- product URLs look like `/shop/...` (or stored `productPageUrl`), not `/products/{sku}`
- no duplicate `<loc>` values
- inactive/deleted records are excluded
- `<lastmod>` is present on dynamic URLs and is the entity `updated_at`, not “now”
- large product catalogs split into `products-1.xml`, `products-2.xml`, …
- frontend performs no catalog/database query to produce the sitemap
